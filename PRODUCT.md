# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users
- Product managers and developers on a desktop, reviewing generated stories, data model, API and tests calmly before a project starts.
- Recruiters and technical interviewers watching a live demo, often over a shared screen in a call.

## Product Purpose
Specforge turns a plain-text idea or a PDF/DOCX requirements document into user stories (Gherkin, Spanish), a relational data model, REST endpoints and test cases, checked for consistency, and ships them into the team's workflow (Jira CSV, GitHub Issues, OpenAPI, PostgreSQL DDL). Success: from requirement to tickets plus API/SQL starting points in one session.

## Positioning
A pipeline of agents (Product Owner → Architect → QA) plus a deterministic validator that sends targeted corrections back to the responsible agent. The correction loop is visible while it runs.

## Capabilities and Constraints
- UI copy in English; generated content in Spanish.
- Free demo runs on the owner's key (limited per IP per day); visitors can bring their own Claude or OpenAI key, held in memory only.
- Stateless server: results live in the browser and can be exported or re-imported as JSON.
- Refine any section with written feedback.

## Brand Commitments
- Name: Specforge.
- Must not look like a generic AI toy (no purple gradients, glows, "magic" sparkle) and must not look corporate or bland.

## Evidence on Hand
No testimonials, customers or metrics exist. Do not fabricate any.

## Product Principles
- The output is the product: generated content must be easy to read and scan.
- Show the mechanism: the agent pipeline and its corrections are visible, not hidden behind a spinner.
- One click to value: examples run without signup or a key.
- Work leaves the app: every result can be exported into tools teams already use.

## Accessibility & Inclusion
WCAG AA contrast in light and dark; legible at screen-share sizes; full keyboard operation.
